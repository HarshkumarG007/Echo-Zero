## 3. History of Critical Issues & Root-Cause Resolutions

### Issue 1: IL2CPP Build Failure
- **Root Cause:** Local Unity 6.3 installation lacked the C++ IL2CPP compiler module.
- **Resolution:** Added automatic Mono backend fallback in `BuildPipeline.cs` (`BuildWindows64_Mono`), allowing immediate headless compilation without external C++ toolchains.

### Issue 2: The "Graybox Ghost" (Empty Scene)
- **Root Cause:** Strict `AGENTS.md` rules prohibited agents from modifying binary `.unity` files by hand, leaving the graybox scene unpopulated.
- **Resolution:** Created procedural editor scripts (`GameAssembler.cs` and `MissingPiecesPatcher.cs`) to generate the entire room geometry, player capsule, colliders, and UI hook programmatically.

### Issue 3: 5,000 FPS GPU Thermal Spike (86°C)
- **Root Cause:** Uncapped framerate in an empty URP scene allowed the RTX 4060 to render at thousands of FPS, drawing peak wattage.
- **Resolution:** Added `Application.targetFrameRate = 60;` and `QualitySettings.vSyncCount = 1;` in `Bootstrap.Awake()`, immediately stabilizing GPU load at ~5%.

### Issue 4: Sentis Intel Graphics Driver Crash (`igc64.dll`)
- **Root Cause:** Unity Sentis defaulted to `BackendType.GPUCompute` on integrated Intel graphics rather than the discrete RTX 4060, triggering an unhandled driver access violation.
- **Resolution:** Formulated **ADR-0005**; removed Sentis from the Phase 3 build path and replaced with a deterministic distance-based heuristic utility scorer. Pinned Sentis backend to CPU for Phase 7.

### Issue 5: Non-Firing Trigger Colliders
- **Root Cause:** Memory fragment pickups lacked a `Rigidbody`, which Unity's physics engine strictly requires on at least one collider in a trigger overlap.
- **Resolution:** Updated `MissingPiecesPatcher.cs` to add a kinematic `Rigidbody` to all interactable pickups.

### Issue 6: Save Checksum Verification Discarding Legitimate Saves
- **Root Cause:** Checksum verification was designed to prevent tampering, but in a single-player offline slice it only served to punish users who hand-edited their saves for testing.
- **Resolution:** Formulated **ADR-0006**; reverted to plain JSON persistence without checksum locks.

## 4. Known Technical Limitations & Constraints

1. **Procedural Geometry:** The environment currently uses graybox primitives (capsules, cubes, cylinders) generated by `GameAssembler.cs`. Textured 3D assets require a dedicated art pass.
2. **Offline-Only:** The game contains no networking, analytics backends, or cloud synchronization by deliberate architectural constraint.
3. **Local Testing Scope:** PlayMode tests currently cover basic movement; a complete automated PlayMode walkthrough from start to finish is proposed for TASK-040.
